# ۰۲ — معماری فنی

> اصل راهنما: **کمترین سرویس، بیشترین خودکارسازی.** یک مخزن، یک اپ Next.js که هم سایت است هم پنل مدیریت هم صف کارها، یک پایگاه‌داده‌ی PostgreSQL.

## ۱. پشته‌ی فناوری

| لایه | انتخاب | چرا |
|---|---|---|
| فرانت و بک‌اند | **Next.js 16 (App Router)** + React 19 + TypeScript | همان پشته‌ی FarsiUI؛ SSR/ISR برای سئو |
| رابط کاربری | **FarsiUI** (base-nova) + Tailwind 4 | ۶۴ کامپوننت و ۴۸۰ بلاک RTL؛ تقویم شمسی؛ ارقام فارسی |
| CMS و پنل مدیریت | **Payload CMS 3** (داخل همان اپ Next) | پنل ادمین آماده، **محلی‌سازی فیلدبه‌فیلد** fa/en/ar، احراز هویت، دسترسی‌ها، صف کار داخلی (Jobs Queue) — بدون نوشتن پنل از صفر |
| پایگاه‌داده | **PostgreSQL 16+** با `pgvector` و `pg_trgm` | یک DB برای داده، جست‌وجوی متنی، فازی و معنایی |
| i18n | `next-intl` برای رابط + محلی‌سازی Payload برای محتوا | مسیرهای `/fa` `/en` `/ar`، تشخیص زبان، hreflang |
| صف و زمان‌بندی | Payload Jobs Queue (cron داخلی)؛ در صورت رشد → Trigger.dev خودمیزبان | کار پس‌زمینه بدون سرویس جدا |
| هوش مصنوعی | لایه‌ی **AI Router** داخلی (`packages/ai`) با چند ارائه‌دهنده | تعویض مدل بدون تغییر کد؛ انطباق با شرایط هر ارائه‌دهنده (سند ۰۹) |
| فایل و تصویر | ذخیره‌ساز S3-سازگار (Cloudflare R2 یا معادل) + `next/image` | نمونه‌خروجی‌ها، کاور، فاکتور |
| ایمیل | Resend یا Postmark (EN/AR) | ایمیل تراکنشی و خبرنامه |
| پیامک | ارائه‌دهنده‌ی داخلی (کاوه‌نگار / SMS.ir) | OTP و اطلاع‌رسانی فارسی |
| تحلیل | **Umami** یا Plausible (خودمیزبان) + **PostHog** برای قیف | بدون کوکی سنگین؛ قیف و فیچرفلگ |
| خطا و آپتایم | Sentry + Uptime Kuma | هشدار به تلگرام |
| شبکه‌های اجتماعی | **Postiz** (متن‌باز، خودمیزبان) یا Buffer | زمان‌بندی خودکار پست در سه زبان |
| افزونه | **WXT** (فریم‌ورک افزونه‌ی چندمرورگری) | کروم/فایرفاکس/اج با یک کد |

## ۲. ساختار مخزن (Monorepo با pnpm + Turborepo)

```
prompt-market/
├─ apps/
│  ├─ web/                 # Next.js + Payload (سایت، پنل، API، Jobs)
│  │  ├─ app/[locale]/     # صفحات عمومی fa/en/ar
│  │  ├─ app/(payload)/    # پنل مدیریت
│  │  ├─ collections/      # تعریف مدل داده‌ی Payload (سند ۰۳)
│  │  ├─ jobs/             # پایپ‌لاین‌ها (سند ۰۴)
│  │  └─ components/ui/    # کامپوننت‌های FarsiUI (کپی‌شده با CLI)
│  ├─ extension/           # افزونه‌ی مرورگر (WXT)
│  └─ telegram-bot/        # ربات (grammY) — سبک، همان DB از طریق API
├─ packages/
│  ├─ ai/                  # AI Router، قالب‌های سیستم، داور (judge)، شمارش هزینه
│  ├─ search/              # نرمال‌سازی fa/ar، رتبه‌بندی ترکیبی
│  ├─ pricing/             # قیمت منطقه‌ای، گرد کردن روانی، شاخص‌گذاری تومان
│  ├─ i18n/                # پیام‌های رابط سه‌زبانه + تست کامل بودن ترجمه
│  └─ config/              # eslint, tsconfig, prettier
├─ infra/                  # docker-compose، پیکربندی Coolify، پشتیبان‌گیری
├─ docs/                   # همین اسناد
└─ .github/workflows/      # CI/CD و cron
```

## ۳. سه‌زبانه و جهت‌ها

| مورد | fa | ar | en |
|---|---|---|---|
| `dir` | rtl | rtl | ltr |
| فونت | Vazirmatn (متن) / Estedad (تیتر) | Noto Naskh Arabic یا Markazi (متن) / Noto Kufi Arabic (تیتر) | Geist / Inter |
| ارقام | فارسی (۱۲۳) | قابل‌انتخاب: عربی-هندی (١٢٣) یا لاتین — پیش‌فرض لاتین برای خلیج | لاتین |
| تقویم | شمسی (`day-picker-persian`) | میلادی (+ هجری در تاریخ‌های نمایشی) | میلادی |
| واحد پول | تومان | USD (نمایش تقریبی AED/SAR) | USD |
| ورود | OTP پیامکی | ایمیل + گوگل | ایمیل + گوگل |

پیاده‌سازی:
- `app/[locale]/layout.tsx` مقدار `lang` و `dir` روی `<html>` و `DirectionProvider` از FarsiUI را تنظیم می‌کند.
- همه‌ی کلاس‌ها **منطقی** (`ms-*`, `pe-*`, `start-*`) — هیچ `left/right` فیزیکی (قانون lint).
- تست CI: هر کلید پیام باید در هر سه زبان وجود داشته باشد؛ اسکرین‌شات Playwright از صفحات کلیدی در سه زبان.

## ۴. جست‌وجو

**نرمال‌سازی (packages/search)** قبل از ایندکس و قبل از کوئری:
- فارسی: `ي→ی`، `ك→ک`، حذف اعراب و تطویل (ـ)، یکسان‌سازی نیم‌فاصله، ارقام فارسی/عربی → لاتین.
- عربی: `أ إ آ → ا`، `ة → ه` (فقط در ایندکس کمکی)، `ى → ي`، حذف تشکیل.

**رتبه‌بندی ترکیبی:**
```
score = 0.45 · text_rank      (ts_rank + شباهت pg_trgm برای غلط تایپی)
      + 0.35 · vector_sim     (pgvector، embedding چندزبانه)
      + 0.20 · quality_score  (سند ۰۳)
      × locale_boost          (۱٫۲ اگر زبان محتوا = زبان کاربر)
```
- embedding چندزبانه یعنی جست‌وجوی فارسی، پرامپت عربی/انگلیسی مرتبط را هم پیدا می‌کند.
- هر جست‌وجوی **بدون نتیجه** ثبت می‌شود → ورودی «کارخانه‌ی محتوا» (سند ۰۴).
- آستانه‌ی مهاجرت: اگر کاتالوگ > ۲۰۰ هزار رکورد یا p95 > ۳۰۰ms شد، Meilisearch اضافه می‌شود.

## ۵. پرداخت

| بازار | روش | نکته |
|---|---|---|
| FA | **زرین‌پال** (اصلی) + **زیبال** (پشتیبان) | نیاز به اینماد و ثبت کسب‌وکار؛ اگر درگاه درخواست از IP خارج را رد کرد، یک سرویس کوچک callback روی سرور داخلی (مثلاً لیارا) |
| EN | **Paddle** یا **Lemon Squeezy** (Merchant of Record) | MoR مالیات/VAT را خودش حساب می‌کند؛ نیاز به نهاد حقوقی مجاز (سند ۰۹) |
| AR (خلیج) | MoR بالا؛ در صورت نیاز بومی‌تر: **Tap Payments** / **PayTabs** | پرداخت با Mada، Apple Pay، KNET |

یک جدول `payments` با فیلد `provider`؛ هر درگاه یک adapter با رابط یکسان (`createCheckout`, `verify`, `refund`, `webhook`).

## ۶. زیرساخت و استقرار

```
             کاربران ─▶ Cloudflare (CDN, WAF, DNS)
                              │
                     ┌────────┴─────────┐
                     ▼                  ▼
           VPS اصلی (Coolify)      سرور کوچک داخلی (اختیاری)
           ├─ web (Next+Payload)   └─ callback درگاه‌های ایرانی
           ├─ PostgreSQL + pgvector
           ├─ Umami، Uptime Kuma، Postiz
           └─ telegram-bot
                     │
               پشتیبان‌گیری روزانه ─▶ R2 (رمزنگاری‌شده، ۳۰ روز)
```
- **Coolify** (PaaS خودمیزبان) استقرار با push، SSL، پشتیبان و لاگ را بدون دانش DevOps فراهم می‌کند.
- منابع شروع: یک VPS با ۴ vCPU / ۸GB RAM کافی است.
- محیط‌ها: `preview` (هر PR) → `staging` → `production` (با تگ).
- نکته‌ی مهم: Next.js 16 + Payload 3 را در هفته‌ی ۱ با یک نمونه‌ی حداقلی تأیید کنید؛ اگر ناسازگاری بود، Next.js 15 با FarsiUI هم کار می‌کند.

## ۷. CI/CD (GitHub Actions)

| Workflow | تریگر | کار |
|---|---|---|
| `ci.yml` | هر PR | lint، typecheck، تست واحد، کامل بودن ترجمه، build |
| `e2e.yml` | هر PR | Playwright: خرید کامل در fa، ورود، جست‌وجو؛ اسکرین‌شات سه زبان |
| `deploy.yml` | push به main / تگ | استقرار staging / production از طریق webhook کولیفای |
| `nightly.yml` | cron شبانه | اجرای پایپ‌لاین‌هایی که نیاز به GitHub دارند (همگام‌سازی CC0)، گزارش وابستگی‌ها |
| `lighthouse.yml` | هفتگی | Core Web Vitals سه زبان؛ شکست اگر LCP > ۲٫۵s |

## ۸. امنیت
- محتوای پرامپت پولی **هرگز** در HTML عمومی، JSON صفحه یا API بدون احراز هویت نمی‌آید (فقط پیش‌نمایش ناقص).
- واترمارک نامرئی متن (کاراکترهای عرض‌صفر با شناسه‌ی خریدار) برای ردیابی نشت.
- محدودیت نرخ (rate limit) روی جست‌وجو، OTP و اجرا؛ Turnstile روی فرم‌ها.
- اسرار در متغیرهای محیطی Coolify؛ هیچ کلیدی در مخزن.
- تأیید امضای webhook همه‌ی درگاه‌ها؛ idempotency روی سفارش.

# ۰۴ — پایپ‌لاین‌های تمام‌خودکار

> این سند قلب «شرکت یک‌نفره» است. هر پایپ‌لاین: تریگر → مراحل → نقطه‌ی دخالت انسانی (اگر هست) → خروجی → هشدار شکست.
> پیاده‌سازی: Jobهای Payload در `apps/web/jobs/` + لایه‌ی `packages/ai`.

## نمای کلی

```
 سیگنال تقاضا ─▶ P1 کارخانه‌ی محتوا ─▶ P2 تست و امتیاز ─▶ P4 بومی‌سازی ─▶ P5 انتشار ─▶ P6 پروموت
      ▲              ▲                        │                                   │
      │         P0 واردات CC0                 ▼                                   ▼
  P9 گزارش ◀──── P8 پایش ◀──── P7 پشتیبانی ◀── P3 جاروی به‌روزرسانی (مدل جدید)   خرید/اجرا
```

| کد | پایپ‌لاین | تریگر | دخالت انسانی |
|---|---|---|---|
| P0 | واردات منابع باز (CC0) | هفتگی | ندارد |
| P1 | کارخانه‌ی محتوا (تولید پرامپت جدید) | روزانه از صف تقاضا | ندارد (فقط موارد مرزی) |
| P2 | تست، داوری و امتیاز کیفیت | هر نسخه‌ی جدید | فقط پرامپت‌های premium با اطمینان پایین |
| P3 | جاروی به‌روزرسانی مدل | افزودن مدل جدید / ماهانه | تأیید دسته‌جمعی |
| P4 | بومی‌سازی سه‌زبانه | بعد از قبولی P2 | نمونه‌برداری ۵٪ |
| P5 | انتشار و سئو | بعد از P4 | ندارد |
| P6 | پروموت چندکاناله | بعد از P5 + زمان‌بندی | ندارد |
| P7 | پشتیبانی و بازگشت وجه | پیام کاربر / درخواست | فقط موارد ارجاع‌شده |
| P8 | پایش و هشدار | پیوسته | فقط هشدار قرمز |
| P9 | گزارش و قیمت‌گذاری پویا | روزانه/هفتگی/ماهانه | خواندن گزارش هفتگی |

## P0 — واردات منابع باز
1. همگام‌سازی مخزن‌های **CC0** یا لایسنس سازگار (مثل prompts.chat / awesome-chatgpt-prompts) از گیت‌هاب.
2. بررسی لایسنس هر منبع (فهرست سفید لایسنس‌ها در کد؛ هر چیز دیگر رد).
3. حذف تکراری‌ها با `externalId` + شباهت embedding > ۰٫۹۲.
4. دسته‌بندی و برچسب‌گذاری خودکار با مدل ارزان (خروجی ساختاریافته‌ی JSON مطابق taxonomy).
5. ورود به‌عنوان `tier=free`، `status=testing` → P2 (تست سبک).
6. ثبت `Source` با لینک و attribution.

> **ممنوع:** کپی محتوای پولی رقبا یا خراش‌دادن (scraping) سایت‌های دارای حق نشر.

## P1 — کارخانه‌ی محتوا
**ورودی:** `DemandSignal`های با بیشترین امتیاز (جست‌وجوی بی‌نتیجه، کوئری‌های Search Console، شکاف دسته‌ها، درخواست کاربران).

1. **برنامه‌ریز:** برای هر سیگنال، مشخص می‌کند: نوع خروجی، مدل هدف، پرسونا، سطح، تعداد متغیر.
2. **نویسنده (مدل قوی):** پرامپت با ساختار استاندارد می‌نویسد:
   `نقش → زمینه → وظیفه → متغیرها → قیود → قالب خروجی → مثال → معیار توقف`.
3. **منتقد:** نسخه‌ی اول را با چک‌لیست نقد می‌کند (ابهام، قیود ناقص، طول، ایمنی) → بازنویسی (حداکثر ۲ دور).
4. **فیلتر سیاست محتوا** (سند ۰۱ بند ۶).
5. ساخت ۳ مجموعه ورودی نمونه برای متغیرها (برای تست P2 و نمونه‌خروجی صفحه).
6. خروجی: `Prompt(status=testing)` + `PromptVersion 1.0.0` → P2.

**ظرفیت:** ۲۰ تا ۵۰ پرامپت در روز، بدون دخالت.

## P2 — تست، داوری، امتیاز
1. برای هر `targetModel` فعال و هر ۳ مجموعه ورودی: اجرای پرامپت و ذخیره‌ی خروجی (`TestRun`).
2. **داور (LLM-as-judge)** با روبریک ثابت امتیاز می‌دهد: ارتباط، کامل بودن، رعایت قالب، کیفیت زبان (جدا برای fa/ar/en)، ایمنی.
   - برای تصویر: داور چندوجهی (vision) + معیار ثبات سبک بین ۳ اجرا.
3. قانون قبولی: میانگین ≥ ۷٫۵ و هیچ معیار < ۶ و ایمنی = قبول.
4. رد → برگشت به P1 با بازخورد داور (حداکثر ۲ بار، سپس آرشیو).
5. قبول → محاسبه‌ی `qualityScore`، انتخاب بهترین خروجی‌ها به‌عنوان `Example`.
6. **صف انسانی** فقط وقتی: `tier=premium` و (اختلاف داورها > ۲ امتیاز یا امتیاز بین ۷٫۵ و ۸).

**کالیبراسیون داور:** ماهانه ۲۰ نمونه را خودتان امتیاز دهید و همبستگی با داور را بسنجید؛ اگر < ۰٫۷ شد روبریک اصلاح شود.

## P3 — جاروی به‌روزرسانی (هسته‌ی وعده‌ی «همیشه به‌روز»)
**تریگر:** افزودن `AIModel` فعال جدید، یا cron ماهانه.
1. انتخاب پرامپت‌های آن خانواده‌ی مدل، به ترتیب فروش.
2. اجرای مجدد P2 روی مدل جدید.
3. اگر امتیاز افت > ۱ کرد → `status=needs_update` → P1 در «حالت بازنویسی» با خروجی‌های شکست‌خورده به‌عنوان ورودی.
4. نسخه‌ی جدید فقط اگر امتیاز بهتر از نسخه‌ی قبل باشد منتشر می‌شود (`semver` minor/major).
5. **اطلاع‌رسانی به خریداران:** «نسخه‌ی ۱٫۳ برای [مدل جدید] آماده است» (ایمیل/پیامک/درون‌سایت) — بازگشت کاربر و فرصت فروش باندل.
6. نشان «✓ تست‌شده روی [مدل] · [تاریخ]» خودکار به‌روز می‌شود.

## P4 — بومی‌سازی سه‌زبانه
1. زبان مبدأ هر پرامپت ثبت می‌شود (هر زبانی می‌تواند مبدأ باشد).
2. **بومی‌سازی، نه ترجمه:** مثال‌ها، نام‌ها، واحد پول، مناسبت‌ها و لحن برای هر بازار عوض می‌شود (مثلاً «نوروز» ↔ «رمضان/عید» ↔ «Black Friday»).
3. متغیرها و ساختار حفظ می‌شود (تست خودکار: همان مجموعه‌ی `{{...}}`).
4. **تست برگشتی:** نسخه‌ی بومی‌شده دوباره از P2 (با داور زبان مقصد) عبور می‌کند.
5. نمونه‌برداری ۵٪ برای بازبینی انسانی (عربی: در صورت امکان یک بازبین عربی‌زبان پاره‌وقت/پروژه‌ای ماهانه).
6. slug، عنوان و توضیح سئو برای هر زبان جداگانه تولید می‌شود.

## P5 — انتشار و سئو
1. تغییر وضعیت به `published`؛ revalidate صفحه‌ها (ISR).
2. به‌روزرسانی sitemap، پینگ IndexNow، ثبت در Search Console API (برای صفحات مهم).
3. ساخت خودکار تصویر OG (قالب برند + نمونه‌خروجی + نام مدل) برای هر زبان.
4. لینک‌سازی داخلی: افزودن به صفحات دسته/برچسب/«پرامپت‌های مشابه» (بر پایه‌ی embedding).
5. اگر پرامپت به باندلی مرتبط است → پیشنهاد افزودن به باندل در گزارش هفتگی.

## P6 — پروموت چندکاناله
برای هر پرامپت منتشرشده (یا هر روز، برترین‌ها):
| کانال | فرمت خودکار | زبان |
|---|---|---|
| تلگرام (کانال + ربات) | «پرامپت روز» + تصویر + لینک | fa، ar |
| اینستاگرام / تیک‌تاک | کاروسل «قبل/بعد» یا ریلز با قالب ثابت (تولید تصویر خودکار، ویدیو از قالب) | fa، ar |
| X (توییتر) | رشته‌توییت ۳–۵ تایی + تصویر | en، ar |
| Pinterest | پین برای پرامپت‌های تصویری | en |
| LinkedIn | پرامپت‌های B2B | en |
| خبرنامه | خلاصه‌ی هفتگی شخصی‌سازی‌شده بر اساس علاقه | هر سه |
- زمان‌بندی از طریق Postiz با بهترین ساعت هر بازار.
- UTM خودکار روی همه‌ی لینک‌ها → P9 بازده هر کانال را می‌سنجد و سهم کانال‌ها را ماهانه تنظیم می‌کند.

## P7 — پشتیبانی و بازگشت وجه
1. همه‌ی پیام‌ها (ایمیل، تلگرام، فرم سایت) به یک صندوق.
2. **دستیار پشتیبانی** با RAG روی FAQ، سیاست‌ها و داده‌ی سفارش همان کاربر پاسخ پیش‌نویس می‌دهد:
   - دسته‌های امن (رمز/ورود، دانلود، «پرامپت کجاست»، فاکتور) → ارسال خودکار.
   - بقیه → صف شما با پاسخ پیش‌نویس (تأیید یک‌کلیکی).
3. **قانون خودکار بازگشت وجه:** ظرف ۷ روز، اگر کمتر از ۳ پرامپت کپی/اجرا شده یا گزارش خرابی تأییدشده → بازپرداخت یا کردیت خودکار. بقیه → صف انسانی.
4. هر «گزارش خرابی» پرامپت → P2 فوری روی آن پرامپت.

## P8 — پایش و هشدار
| رویداد | سطح | کانال |
|---|---|---|
| سایت یا درگاه پرداخت از دسترس خارج | 🔴 | تلگرام فوری + پیامک |
| نرخ خطای پرداخت > ۵٪ در ۱ ساعت | 🔴 | تلگرام فوری |
| هزینه‌ی روزانه‌ی API هوش مصنوعی > سقف | 🟠 | تلگرام؛ پایپ‌لاین‌های P1/P3 خودکار متوقف |
| شکست Job بیش از ۳ بار | 🟠 | خلاصه‌ی روزانه |
| افت ترافیک ارگانیک > ۳۰٪ هفته‌به‌هفته | 🟠 | گزارش هفتگی |
| LCP > ۲٫۵s | 🟡 | گزارش هفتگی |

## P9 — گزارش و قیمت‌گذاری پویا
- **روزانه (ساعت ۸ صبح، تلگرام):** فروش، درآمد، کاربر جدید، صف انسانی، هشدارها — یک پیام کوتاه.
- **هفتگی:** KPIها (سند ۰۸)، برترین/بدترین پرامپت‌ها، ۱۰ سیگنال تقاضای برتر، پیشنهاد باندل‌های جدید، بازده کانال‌ها.
- **ماهانه:** شاخص‌گذاری قیمت تومان (سند ۰۵)، آزمون A/B قیمت تمام‌شده، کالیبراسیون داور، هزینه‌ها.

## لایه‌ی AI (packages/ai)

```ts
// نمای مفهومی
ai.run({ task: "write" | "critique" | "judge" | "localize" | "classify" | "support",
         input, schema?, locale?, budgetUsd? })
```
- **نقشه‌ی وظیفه → مدل** در پیکربندی (نه در کد): وظایف سنگین (نوشتن، نقد) → مدل قوی؛ داوری/دسته‌بندی/بومی‌سازی انبوه → مدل سریع‌تر و ارزان‌تر.
- خروجی ساختاریافته (JSON Schema) برای همه‌ی مراحل ماشینی.
- **Batch API** برای همه‌ی کارهای غیرفوری (P0، P3، P4) — حدود ۵۰٪ ارزان‌تر.
- **Prompt caching** برای قالب‌های سیستمی ثابت و روبریک داور.
- ثبت هزینه‌ی هر فراخوانی روی `Job` و سقف بودجه‌ی روزانه.
- ارائه‌دهندگان قابل تعویض؛ انتخاب ارائه‌دهنده تابع **شرایط استفاده و مناطق پشتیبانی‌شده‌ی هر ارائه‌دهنده** است (سند ۰۹).

### برآورد هزینه‌ی تولید (نمونه با مدل‌های Claude، قیمت‌های اعلام‌شده در مهر ۱۴۰۵)

| مدل | ورودی / خروجی به ازای ۱ میلیون توکن |
|---|---|
| Claude Opus 5.5 (`claude-opus-5-5`) | ۴ / ۲۰ دلار |
| Claude Sonnet 5.5 (`claude-sonnet-5-5`) | ۲ / ۱۰ دلار |
| Claude Haiku 5.5 (`claude-haiku-5-5`) | ۰٫۱۰ / ۰٫۵۰ دلار |

| کار | فرض | هزینه‌ی تقریبی |
|---|---|---|
| نوشتن + نقد یک پرامپت premium (Opus 5.5) | ~۶k ورودی، ~۴k خروجی | ~۰٫۱۰ دلار |
| داوری ۹ اجرای تست (Haiku 5.5) | ~۲۷k ورودی، ~۴k خروجی | ~۰٫۰۰۵ دلار |
| بومی‌سازی به ۲ زبان (Sonnet 5.5، Batch) | ~۴k ورودی، ~۴k خروجی | ~۰٫۰۲۴ دلار |
| **جمع هر پرامپت premium (بدون هزینه‌ی اجرای مدل‌های هدف)** | | **~۰٫۱۳ دلار** |
| واردات و دسته‌بندی و بومی‌سازی ۵,۰۰۰ پرامپت CC0 (Haiku 5.5، Batch) | | **~۵ دلار** |

- هزینه‌ی **اجرای تست روی مدل‌های هدف** (GPT، Gemini، Midjourney و…) جداست و به نرخ هر ارائه‌دهنده بستگی دارد؛ بودجه‌ی پیشنهادی ماه اول: ۱۰۰ تا ۲۰۰ دلار.
- قیمت‌ها را قبل از اجرا از صفحه‌ی رسمی هر ارائه‌دهنده دوباره چک کنید.
